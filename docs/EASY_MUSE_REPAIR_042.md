# Easy Muse repair 0.4.2

Use **Find & repair errors** in AI analysis or Code Studio. RESCUE runs source checks, groups confirmed failures by file, ranks parser errors first and distinguishes unresolved dependencies from repairable code. Select **Prepare recommended repair**; the exact diagnostic is supplied automatically, with no blank issue form. A live Meta request returns the changed source and a before/after comparison. Click **Repair sandbox** to apply that exact change. Checks run again; newly introduced errors trigger rollback. Existing unrelated errors may remain, with resolved/remaining counts. Continue through the remaining repairable files, then run independent application tests.

The activity panel animates during a real request and reports the model request ID, selected checks, result and changed source. Monaco keeps syntax diagnostics but no longer presents missing browser React/Next dependencies as semantic code errors. The backend's bounded environment-aware diagnostics remain available under Diagnostics.

The former secret guard treated assignments such as `const token = await readToken()` as credentials. The source-specific guard now distinguishes variable/environment references from credential-shaped literal values and known provider/private-key patterns. Actual detected literal values are withheld from Meta; repair planning shows file/line/category without exposing values. This is a conservative detector, not a guarantee to detect every possible secret. Environment files remain excluded.

If the plan says ENVIRONMENT REQUIRED, RESCUE has no confirmed safe source replacement. Install/resolve the project's dependencies in an authorized isolated runner before attempting a dependency-aware typecheck or runtime repair. An empty error list does not certify the project, and red editor marks are not themselves proof of a runtime defect. A different observed behavior can still be reported using the optional advanced issue flow.

81 regression tests and 92 module syntax checks passed during implementation. New tests cover secret false positives, literal protection, ranked repair choices, environment separation, newly introduced errors and fixing one error while retaining another existing failure. Exact sandbox-change approval remains required. Production and TASTE were not changed by sandbox repairs.
